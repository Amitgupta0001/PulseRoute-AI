## 1. Project Overview

This transcript logs the AI-assisted development process for the **Message Notification Router** system submitted to the **HackerRank Orchestrate AI Hackathon**. 

The goal of the project is to classify incoming WhatsApp notifications—including text messages, image attachments, and voice notes—into three discrete routing actions (`notify`, `digest`, `mute`), alongside categorized message types, human-readable reasons, calibrated confidence scores, and historical evidence message references.

This document records the prompt-and-response iterations, engineering decisions, codebase audits, multimodal integrations, and verification steps completed during development.

### 3.3 Routing Improvements

**Developer Prompt:**
> "Review the routing decision engine in `router.py` and ensure rules follow a clear priority cascade."

**AI Response Summary:**
> Evaluated `NotificationRouter.route()` logic. Confirmed an 11-stage priority sequence:
> 1. Scam & High Risk (forwarded count, scam terms, high report rate) $\rightarrow$ `mute/scam`
> 2. Verified Bank Payments $\rightarrow$ `notify/payment`
> 3. Promotional Content (check user business opt-in settings) $\rightarrow$ `digest` or `mute`
> 4. Family Group Messages $\rightarrow$ `notify/personal`
> 5. School Group Announcements (event terms) $\rightarrow$ `notify/event`
> 6. Work Group Discussions (check 30-day reply activity) $\rightarrow$ `notify` or `digest`
> 7. User-Muted Groups $\rightarrow$ `mute/unknown`
> 8. Do-Not-Disturb Quiet Hours $\rightarrow$ `digest/unknown`
> 9. Historical User Reaction (high reply rate vs high dismiss rate)
> 10. Urgent Personal Messages $\rightarrow$ `notify/urgent`
> 11. Default Fallback $\rightarrow$ `digest/unknown`
>
> Identified and recommended removing the redundant `FeatureEngine.build()` invocation inside `router.py`.

**Action Taken:**
Cleaned up duplicate feature extraction calls in `router.py`.

## 4. Major Engineering Decisions

| Engineering Decision | Rationale |
| :--- | :--- |
| **Deterministic Priority Cascade** | Chosen over pure LLM calls to eliminate API latency, guarantee 100% reproducible results, and operate offline without external services. |
| **In-Memory Hash Map Caching** | Indexing relational DataFrames into dictionary maps during startup converts context queries into constant-time lookups during batch processing. |
| **Hybrid Evidence Score** | Combining text similarity with metadata matching prevents false evidence associations across unrelated senders. |
| **Bounded Confidence Scores** | Constraining confidence outputs between 0.70 and 0.95 provides calibrated probability estimates while avoiding overconfident extreme values (1.0 or 0.0). |
| **Pre-Extraction Media Normalization** | Converting images (OCR) and audio (Speech-to-Text) into text before feature extraction allows downstream engines to treat all notifications uniformly. |

   - *Challenge:* Terminal execution threw `ModuleNotFoundError: No module named 'faster_whisper'`, bypassing voice note transcription.

   - *Challenge:* `generate_output.py` handled OCR and Speech, but `main.py` single-message demo did not trigger media engines.
   - *Fix:* Added `OCREngine` and `SpeechEngine` initialization and extraction logic to `main.py`.

3. **Redundant Feature Extraction Calls:**
   - *Challenge:* `router.py` re-executed `FeatureEngine.build()`, duplicating calculations already performed in the pipeline loop.
   - *Fix:* Streamlined `router.py` to accept pre-built feature dictionaries.
