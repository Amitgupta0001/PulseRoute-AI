## Executive Summary

This AI Development Transcript documents the end-to-end engineering lifecycle, architectural auditing, multimodal integration, feature engineering, evidence retrieval optimization, confidence calibration, and technical documentation for the **Message Notification Router** system submitted to the **HackerRank Orchestrate AI Hackathon**.

Over the development lifecycle, the system evolved from a partially connected prototype into a high-performance, deterministic, multimodal AI routing engine. Operating over 12 relational CSV datasets, the system processes text messages, image posters/flyers via EasyOCR, and voice notes via Faster-Whisper to classify incoming notifications into three discrete routing actions (`notify`, `digest`, `mute`), calibrated confidence scores (`0.70` to `0.95`), auditable decision reasons, and semicolon-delimited historical evidence references (`evidence_message_ids`).

Key engineering milestones achieved:
1. **$O(1)$ Context Indexing:** Conversion of 12 relational DataFrames into in-memory hash maps, eliminating $O(N)$ repeated scanning bottlenecks.
2. **Multimodal Wiring:** Full integration of EasyOCR and Faster-Whisper engines across single-message and batch prediction pipelines.
3. **11-Stage Priority Cascade:** Implementation of a strict deterministic rule hierarchy prioritizing security (scams) and transactional updates over general user preferences.
4. **Hybrid Evidence Retrieval:** Formulation of a weighted similarity model ($0.6 \times \text{text} + 0.4 \times \text{metadata}$) for historical evidence selection.
5. **Dynamic Bounded Calibration:** Min-max constrained confidence scoring between `[0.70, 0.95]`.

## Phase 1 – Problem Understanding & Challenge Requirements

### Challenge Context & Objective
Messaging platforms like WhatsApp present severe notification fatigue. Users receive heterogeneous alerts—family emergencies, work discussions, bank updates, promotional broadcasts, noisy group chats, and malicious scams. 

The objective was to build an intelligent, context-aware notification router that evaluates incoming messages in `dataset/messages.csv` and outputs predictions into a 6-column `output.csv`:

- `action`: Routing decision (`notify`, `digest`, `mute`).
- `message_type`: Message classification (`personal`, `urgent`, `event`, `payment`, `business_update`, `promotion`, `greeting`, `forward`, `spam`, `scam`, `unknown`).
- `reason`: Human-readable audit explanation.
- `confidence`: Calibrated score between `0.0` and `1.0`.
- `evidence_message_ids`: Top-3 historical message IDs (`msg_1;msg_2;msg_3`) or `"none"`.

### Operational Requirements
- **Multimodal Support:** Messages containing image attachments or voice notes must have text extracted via OCR or Speech-to-Text before downstream evaluation.
- **Personalization:** Routing decisions must adapt based on individual user interaction metrics (reply, open, dismiss, report rates), quiet hours, and opt-in settings.
- **Safety First:** Scam or phishing threats must override user preferences and trigger immediate muting.

## Phase 2 – System Architecture & Module Design

### High-Level Architecture Design
The architecture was structured into a modular pipeline separating data ingestion, context indexing, media extraction, feature engineering, decision routing, evidence ranking, and output generation.

```mermaid
graph TD
    A["Incoming Messages (messages.csv)"] --> B["DataLoader Engine"]
    B --> C["IncomingMessage Model"]
    
    C --> D{"Media Check"}
    D -- "media_type == image" --> E["OCREngine (EasyOCR)"]
    D -- "media_type == voice" --> F["SpeechEngine (Faster-Whisper)"]
    D -- "text" --> G["ContextRetriever (O(1) Hash Maps)"]
    E --> G
    F --> G
    
    G --> H["NotificationRouter"]
    H --> I["FeatureEngine (Regex & Behavioral Ratios)"]
    H --> J["ConfidenceEngine (Dynamic Calibration)"]
    
    G & C --> K["EvidenceRetriever (Hybrid Ranking)"]
    
    H & J & K --> L["Output Generator"]
    L --> M["output.csv"]
```

### Module Responsibilities
- `code/loader.py`: Ingests all 12 relational CSV datasets into memory.
- `code/models.py`: Defines dataclasses for `IncomingMessage` (with NaN sanitization) and `UserContext`.
- `code/context_retriever.py`: Constructs in-memory hash maps for $O(1)$ contextual lookups.
- `code/feature_engine.py`: Computes regex keyword flags, user interaction ratios, and DND time window checks.
- `code/router.py`: Evaluates an 11-stage priority decision rule hierarchy.
- `code/confidence.py`: Computes dynamic confidence scores bounded between `0.70` and `0.95`.
- `code/evidence.py`: Executes hybrid text similarity and metadata evidence ranking.
- `code/media/ocr.py`: Wraps EasyOCR reader for image text extraction.
- `code/media/speech.py`: Wraps Faster-Whisper model for audio transcription.
- `code/generate_output.py`: Orchestrates batch inference and CSV exporting.

## Phase 3 – Dataset Analysis & Relational Indexing

### Dataset Ingestion Matrix
The system synthesizes 12 relational tables to construct a complete context graph per incoming message:

| Dataset | Primary Keys / Foreign Keys | Extracted Context & Purpose |
| :--- | :--- | :--- |
| `messages.csv` | `message_id`, `user_id`, `sender_user_id`, `group_id`, `business_id` | Incoming notifications requiring routing decisions |
| `users.csv` | `user_id` | Quiet hours (`do_not_disturb_window`), aggregate open/reply/dismiss/report counts |
| `groups.csv` | `group_id` | Group metadata (`group_type`: family, school, work; admin lists; member count) |
| `group_members.csv` | `group_id`, `user_id` | Role, `replies_sent_30d`, individual `muted_by_user` flag |
| `business_accounts.csv` | `business_id` | `verified` flag, business `category` (e.g. bank), account age |
| `user_business_history.csv` | `user_id`, `business_id` | Opt-in preferences (`allows_promotions`), order/booking transaction history |
| `message_history.csv` | `message_id`, `user_id`, `sender_user_id` | Historical message archive used as memory for evidence retrieval |
| `message_events.csv` | `message_id`, `event_type` | User interaction reactions (`opened`, `replied`, `dismissed`, `reported`) |
| `images.csv` | `image_id`, `file_path` | Mapping for image files stored in `dataset/media/images/` |
| `voice_notes.csv` | `voice_note_id`, `file_path` | Mapping for voice files stored in `dataset/media/audio/` |
| `daily_notification_summary.csv` | `user_id`, `date` | Historical daily notification counts to track volume |
| `sample_messages.csv` | `message_id` | Baseline reference format for output schema and labels |

### Hash Indexing Optimization
Initial analysis revealed that filtering pandas DataFrames repeatedly inside prediction loops caused severe performance bottlenecks. To achieve sub-second latency, `ContextRetriever` pre-indexes all relational datasets into nested Python dictionaries during initialization:

```python
self._users = loader.users.set_index("user_id").to_dict(orient="index")
self._groups = loader.groups.set_index("group_id").to_dict(orient="index")
self._group_members = loader.group_members.set_index(["group_id", "user_id"]).to_dict(orient="index")
```

## Phase 4 – Feature Engineering & Context Retrieval

### Feature Engine Design
The `FeatureEngine` extracts behavioral and keyword signals from incoming messages and user context:

1. **Regex Word Boundary Keyword Matching:**
   Uses regex pattern matching with `\b` word boundaries to prevent false substring triggers:
   - `PAYMENT_KEYWORDS`: `payment`, `bank`, `otp`, `account`, `transaction`, `credited`, `debited`
   - `URGENT_KEYWORDS`: `urgent`, `asap`, `emergency`, `important`, `help`
   - `PROMOTION_KEYWORDS`: `offer`, `discount`, `sale`, `cashback`, `deal`, `coupon`
   - `SCAM_KEYWORDS`: `winner`, `lottery`, `prize`, `claim`, `crypto`, `investment`, `verify account`
   - `EVENT_KEYWORDS`: `event`, `meeting`, `webinar`, `schedule`, `invitation`

2. **User Interaction Ratios:**
   Calculates user-specific interaction metrics from historical event logs:
   $$\text{Reply Rate} = \frac{\text{Replied Messages}}{\max(1, \text{Total History Messages})}$$
   $$\text{Dismiss Rate} = \frac{\text{Dismissed Messages}}{\max(1, \text{Total History Messages})}$$
   $$\text{Report Rate} = \frac{\text{Reported Messages}}{\max(1, \text{Total History Messages})}$$

3. **Do-Not-Disturb (DND) Time Window Validation:**
   Parses `do_not_disturb_window` strings (e.g., `"22:00-07:00"`). Checks whether the incoming message creation timestamp falls within the quiet hour boundaries.

## Phase 5 – Multimodal Processing (OCR & Speech Integration)

### Media Text Extraction Architecture
Incoming messages with empty text fields but valid media attachments undergo automated multimodal processing:

1. **EasyOCR Image Engine (`code/media/ocr.py`):**
   - Resolves `media_id` against `images.csv` to acquire image file path.
   - Evaluates file existence in `dataset/media/images/`.
   - Executes EasyOCR reader (`easyocr.Reader(['en'])`) to extract text tokens from screenshots, flyers, or posters.
   - Reassigns extracted text directly to `message.message_text`.

2. **Faster-Whisper Speech Engine (`code/media/speech.py`):**
   - Resolves `media_id` against `voice_notes.csv` to acquire audio file path.
   - Evaluates file existence in `dataset/media/audio/`.
   - Executes Faster-Whisper (`WhisperModel("tiny")`) to transcribe voice note recordings into text.
   - Reassigns transcript string directly to `message.message_text`.

### Pipeline Invariance
By populating `message_text` prior to feature extraction, downstream engines (`FeatureEngine`, `NotificationRouter`, `EvidenceRetriever`) process multimodal text through the exact same feature engineering pipeline as standard text notifications.

## Phase 6 – Evidence Retrieval & Confidence Calibration

### Hybrid Evidence Scoring Engine
The `EvidenceRetriever` identifies historical messages in `message_history.csv` that substantiate the current decision:

1. **Hybrid Scoring Formula:**
   $$\text{Total Score} = (\text{Text Similarity} \times 0.6) + (\text{Metadata Score} \times 0.4)$$
   Text similarity is calculated using `rapidfuzz.fuzz.token_sort_ratio`.

2. **Metadata Weight Distribution:**
   - Sender User ID Match: $+45.0$
   - Business ID Match: $+35.0$
   - Media Type Match: $+25.0$
   - Group ID Match: $+20.0$
   - Conversation Type Match: $+15.0$

3. **Selection & Formatting:**
   Historical candidate messages with a score $> 40.0$ are sorted descending. Up to 3 unique message IDs are joined into a semicolon-separated string (e.g. `"message_0101;message_0102;message_0103"`). If no message meets the threshold, `"none"` is returned.

### Bounded Confidence Calibration
The `ConfidenceEngine` computes dynamic confidence scores starting from a base score of `0.75`:

| Feature Condition | Delta Adjustment |
| :--- | :---: |
| Verified Business Account | `+0.04` |
| Known Business Subscriber | `+0.03` |
| Payment Keywords Present | `+0.03` |
| Urgent Keywords Present | `+0.03` |
| Event Keywords Present | `+0.02` |
| Scam/Phishing Keywords Detected | `+0.05` |
| User Report Rate $\ge 20\%$ | `+0.04` |
| User Reply Rate $\ge 40\%$ | `+0.03` |
| User Dismiss Rate $\ge 50\%$ | `+0.03` |
| Unallowed Promotional Message | `+0.02` |
| Non-Urgent DND Delivery | `-0.02` |

The aggregated score is clamped strictly between `[0.70, 0.95]` and rounded to two decimal places.

## Engineering Decisions

| Decision | Engineering Rationale |
| :--- | :--- |
| **Deterministic Priority Hierarchy** | Selected over pure LLM calls to ensure zero inference latency, 100% reproducible predictions, and zero external API dependencies. |
| **In-Memory Hash Map Caching** | Converted 12 relational DataFrames into dictionary lookups during startup to achieve $O(1)$ retrieval speeds and sub-second batch runs. |
| **Hybrid Evidence Scoring Formula** | Combined token-sort similarity ($60\%$) with metadata matching ($40\%$) to prevent false evidence matches across unrelated senders. |
| **Bounded Min-Max Confidence** | Bounded confidence scores within `[0.70, 0.95]` to provide calibrated probability estimates while avoiding overconfident edge values (`1.0` / `0.0`). |
| **Multimodal Text Pre-Processing** | Extracted text from images and voice notes prior to feature building, maintaining pipeline invariance across text and media notifications. |
| **Regex Boundary Pattern Matching (`\b`)** | Used word boundaries in keyword regex patterns to prevent false substring matches (e.g. preventing `"car"` inside `"scam"`). |

## Challenges Encountered & Resolutions

1. **Missing Audio Dependency (`faster-whisper`):**
   - *Challenge:* Initial environment lacked the `faster-whisper` package, causing voice transcription calls to fall back without audio text.
   - *Resolution:* Installed `faster-whisper` and its underlying `ctranslate2` dependencies in `.venv`, enabling transcription models.

2. **Performance Bottlenecks in Batch Inference:**
   - *Challenge:* Filtering pandas DataFrames inside nested loops for each message caused slow execution.
   - *Resolution:* Pre-indexed all 12 datasets into dictionary hash maps in `ContextRetriever`, converting queries to $O(1)$ lookups.

3. **Pipeline Inconsistencies between `main.py` and `generate_output.py`:**
   - *Challenge:* `generate_output.py` handled media extraction, but `main.py` demo bypassed OCR and Speech engines.
   - *Resolution:* Refactored `main.py` to invoke `OCREngine` and `SpeechEngine` prior to feature building.
